# Page layout rules of the preview (measured; Hangul 2024 pages at 96 dpi and the `hp:linesegarray` it stores)

Ids P01-P20. Shared OWPML rules stay in `docs/rules.md`; these are about where Hangul puts things on a page.

| id | rule | evidence |
|---|---|---|
| P01 | A line has text height S (the largest character size on it), baseline 0.85 x S below the line top, and spacing below it: PERCENT L: pitch = S x L / 100 (spacing = S x (L - 100) / 100); FIXED v: pitch = v (text stays at the top); AT_LEAST v: pitch = max(v, S); BETWEEN_LINES v: pitch = S + v. An inline picture or table makes S its height; the spacing stays (L - 100) % of the text size. | lineseg vertsize/baseline/spacing of the 238 fixtures (435 lines): baseline / vertsize = 0.85 in 433; P:para_line_fixed/atleast/between/percent, picture_add |
| P02 | A paragraph is before + its lines + after; neighbouring `before`/`after` are added, never merged (vertpos 2040 = 1440 line + 200 after + 400 before). | S:gongmun_tongji lineseg |
| P03 | The `before` of the paragraph that follows a block table is dropped; the table's outer margin (default 1 mm) is kept above and below it, and the `before` of the table's own paragraph is not used. | M:gongmun_tongji (stamp box and the paragraphs around the first table, 0 px off) |
| P04 | Paragraph border/fill: the box starts at the paragraph top (spacing before inside) minus the top offset and ends at the paragraph bottom (spacing after inside) plus the bottom offset; the offsets take no room in the flow. | M:gongmun_tongji (box 755-817 px), gyehoekseo headings |
| P05 | A table cell's content height leaves out the line spacing below the last line (W04); a row is at least its `cellSz` height. | M:gongmun_tongji, hoeuirok (rows within 1 px) |

| P18 | A table at a page end (`page_break` cell, the default): a row that does not fit is cut inside its cells, not moved, when a line of a cell fits. Each part is laid out as a row of its own: its height is its highest cell (content without the last line's spacing below, plus padding; the first part at least the row's own `cellSz` height), the cells are aligned in it (`valign`, default centre) and it has its own top and bottom edges (the bottom of the first part is drawn at the page end). A part that is still too high is cut again. Not cut: header rows, tables with `page_break` table / none (whole rows go on). Merged rows (`rs`, `page_break` cell): the rows tied by row spans are one flow atom, cut like a row; the table keeps its outer margin below (1 mm) under every part, so a part ends at `end` = the page end less that margin, and the last line of a cell needs its own height (the spacing below it is not asked for) plus the 0.12 mm bottom border above `end`.
