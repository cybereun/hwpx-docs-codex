# Objects, second set: rules (Hangul 2024)

Rules OB01-OB20 for this package (`lib/hwpx_docs/objects2/`). Evidence keys as in `docs/rules.md` (S: sample, P: minimal-difference pair, RT: round trip, B: builder output). Fixtures: `fixtures/` in this folder. `corpus.py` makes the Hangul samples (dev tool, needs Hangul 2024; `corpus.log` has every try and every error).

How a sample is made (hidden Hangul, `render/hwpcom.py`, security module on): `InsertCtrl("$rec"/"$lin"/"$ell"/"$arc", ShapeObject set)` inserts a drawing object; `ctrl.Properties` / `ctrl.Properties = set` reads and writes its parameter sets (sub sets `ShapeDrawImageAttr`, `ShapeDrawLineAttr`, `ShapeCaption`, `ShapeDrawTextart`; item names are case sensitive: `Style`, not `style`). What COM cannot make (polygon, curve, connector, group, OLE) is written as OWPML by hand from the public OWPML element names, opened by Hangul and saved again; a kind counts as confirmed only when Hangul keeps it and draws it (the render was looked at). `RT:` = the fixture reads, builds and reads to the same spec (self-test). `B:build_*` = builder output that Hangul opened (no repair prompt), saved again and drew as expected.

| OB19 | OLE object that embeds a file: `hp:ole objectType="EMBEDDED" binaryItemIDRef="ole1" hasMoniker="0" drawAspect="CONTENT" eqBaseLine="0"` with `hc:extent x y` (= the size), `lineShape` (style NONE), `sz` (default 7574 x 6225 hu = 26.72 x 21.96 mm), `pos`, `shapeComment` "OLE 개체입니다.\n원본 파일의 이름은 <name without extension>입니다."; `numberingType="PICTURE"`. The part is `BinData/ole1.ole` (manifest `media-type="application/ole"`; the builder's `isEmbeded="1"` is accepted by Hangul). Content of the part: 4 bytes little endian = the length of what follows, then a compound file (CFB v3, 512-byte sectors, 64-byte mini sectors) with the streams `\x01CompObj` (76 constant bytes: the class "OLE Package") and `\x01Ole10Native`; the root entry has the class {0003000C-0000-0000-C000-000000000046}. Ole10Native: DWORD length of the rest, WORD 2, label (file name) + NUL, source path + NUL, `00 00 03 00`, DWORD length of the temp path + 1, temp path + NUL, DWORD length of the file, the file, then three UTF-16 names each as DWORD characters + characters: temp path, label, source path. The builder writes `C:\temp\<name>` for both paths (never a real folder); a file of 3 KB or more is stored in regular sectors, smaller ones in the mini stream (tested up to 40 KB). Spec `{"ole": {"src": "a.txt", "w", "h", "inline", "pos", "wrap", "side", "caption"}}`; the reader saves the embedded file next to the spec under its label and gives `src`. An OLE object that is not an embedded "Package" file (Excel, ...) is not parsed: raw OWPML. | S:ole_file (read), build_ole (built, opened, saved, read back byte for byte); self-test of the compound file |
