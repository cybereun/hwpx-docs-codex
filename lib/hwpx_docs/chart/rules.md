# Native Hangul chart: rules (Hangul 2024)

Rules CH01-CH11 for this package (`lib/hwpx_docs/chart/`). Evidence keys as in `docs/rules.md` (S: sample, P: minimal-difference pair, RT: round trip, B: builder output). Fixtures: `fixtures/` in this folder.

Pairs `P:chart_<x>` are `chart_<x>_A.hwpx` (base: bar chart, 3 series, 4 categories) and `chart_<x>_B.hwpx` (one change).
Hangul COM has no parameter set for chart data or kind (CH01), so a pair is made like this: Hangul inserts the chart
(`S:chart_default`), the change is written into `Chart/chart1.xml`, Hangul opens the file and saves it again. Every
fixture is a Hangul-saved file; the OLE fallback and the preview image are cut out (size) and creator/lastsaveby are
`hwpx-docs`. `RT:chart_*` = `hd roundtrip` on 13 of them: ink difference 0.00. `B:<name>` = a builder output (spec ->
HWPX) that Hangul opened (no repair prompt) and drew as expected; `B:n_*` files are development records, not shipped.

| id | rule | evidence |
|---|---|---|
| CH01 | COM `HAction.Run("InsertChart")` inserts the default chart (horizontal clustered bars, categories 항목 1-4, series 계열 1-3, values 4.3 2.4 2 / 2.5 4.4 2 / 3.5 1.8 3 / 4.5 2.8 5) into the caret paragraph and opens a WPF window "차트 데이터 편집" that hwpcom's watchdog closes after 8 s. No `HParameterSet` for chart actions exists (`HChangeChart`, `HChartType` ... missing). Running `ChangeChart` or `ChartLayoutList` with no set changes the chart (title and the first series data disappeared). | S:chart_default; test probe3 |
| CH02 | A chart is two things: the part `Chart/chartN.xml` (OOXML chart: root `c:chartSpace`, namespace `.../drawingml/2006/chart`, plus the Hangul style extension `ho:hncChartStyle layoutIndex colorIndex styleIndex`) and an `hp:chart` in the section. Hangul does NOT list the chart part in `content.hpf` (the manifest has header, section, settings only); the builder does the same. | S:chart_default; B:n_bar (open OK) |
| CH03 | Section form (inside the paragraph's `hp:run`, which ends with `<hp:t/>`): `hp:switch` > `hp:case hp:required-namespace="http://www.hancom.co.kr/hwpml/2016/ooxmlchart"` > `hp:chart id zOrder numberingType="PICTURE" textWrap textFlow="BOTH_SIDES" lock="0" dropcapstyle="None" chartIDRef="Chart/chart1.xml"` with children `hp:sz`, `hp:pos`, `hp:outMargin` (in this order). `hp:default` > `hp:ole` is the old-reader fallback. Hangul's default: `treatAsChar="0"`, `textWrap="SQUARE"`, vertRelTo PARA, horzRelTo COLUMN, 113.8 x 66.1 mm (32250 x 18750 hu). Inline (`treatAsChar="1"`, `TOP_AND_BOTTOM`) and floating (`pos` offsets) both draw correctly. | S:chart_default; B:n_text |
| CH04 | The OLE fallback is not needed: with no `hp:default`, no `BinData/ole1.ole` (about 270 KB, a compound file; manifest item `ole1`, `application/ole`, `isEmbeded="0"`), no manifest item and no `Preview/PrvImage.png`, Hangul 2024 opens the file with no prompt and draws the same chart (ink 0.00). A bare `hp:chart` with no `hp:switch` also opens. On the next save Hangul writes the OLE again. Hangul versions without OOXML chart support: not tested. The builder writes the `hp:case` only. | test: OLE cut out of a Hangul file; RT:chart_default (0.00) |
| CH05 | Data lives in the caches of the part: series name `c:ser/c:tx/c:strRef/c:strCache`, categories `c:cat/c:strRef/c:strCache`, values `c:val/c:numRef/c:numCache` (`c:formatCode General`, `c:ptCount`, `c:pt idx/c:v`). The formulas (`Sheet1!$B$1`, `Sheet1!$A$2:$A$5`, `Sheet1!$B$2:$B$5`) point at a sheet that is not in the file; Hangul draws from the caches, and rebuilds its OLE data from them. Changing one `c:v` changes the bar and the axis scale (5 -> 10). | P:chart_value; P:chart_series_name |
| CH06 | Kind = group element in `c:plotArea`. `c:barChart`: `c:barDir val="bar"` = HORIZONTAL (Hangul's default), `col` = vertical; `c:grouping` `clustered` or `stacked` (stacked also `c:overlap val="100"`). `c:lineChart`: `c:grouping standard`, per series `c:marker/c:symbol` (`none`, `circle` ...) and `c:smooth`, group `c:marker val="1"`. `c:pieChart`: no axes, one series, `c:dPt` per slice for colours. Combined chart = `c:barChart` and `c:lineChart` side by side in one `c:plotArea`, both naming the same two `c:axId`. Axes: horizontal bar has catAx `axPos l` and valAx `b`; the other kinds `b` and `l`. | P:chart_type, chart_direction, chart_stack; S:chart_pie, chart_combo |
| CH07 | Title: `c:title/c:tx/c:rich` with an `a:r/a:t` run. A `c:title` with no text (Hangul's default) draws the placeholder "차트 제목". No title: leave `c:title` out and write `c:autoTitleDeleted val="1"`. A pie with an empty title shows its series name. Axis titles: a `c:title` inside `c:catAx` / `c:valAx` (after `c:delete`, before `c:majorTickMark`). | P:chart_title, chart_axis_title; S:chart_pie |
| CH08 | Legend: `c:legend/c:legendPos` `r`, `l`, `t`, `b`; no `c:legend` = no legend. | P:chart_legend, chart_legend_none |
| CH09 | Colour: `c:ser/c:spPr/a:solidFill/a:srgbClr val="RRGGBB"` (Hangul writes lower case); for a line the colour goes in `c:spPr/a:ln` and the marker `c:spPr`. With no `c:spPr` Hangul takes its own palette (blue, orange, grey, yellow). | P:chart_color; B:n_line |
| CH10 | Also accepted and drawn: data labels `c:dLbls` in `c:ser` before `c:cat` (`showVal` / `showPercent` = 1, the others 0); axis range `c:scaling` with `c:max` / `c:min` after `c:orientation`; no grid = no `c:majorGridlines`; with negative values the category axis needs `c:tickLblPos val="low"` (the default `nextTo` puts the labels on the zero line, over the bars); chart font in the root `c:txPr` (`a:defRPr sz` in 1/100 pt, `a:latin`, `a:ea`, `a:cs`, `a:sym typeface`, default 함초롬돋움 10 pt). | B:n_bar, n_line, n_pie |
| CH11 | Child order need not follow the OOXML schema: Hangul writes `axId, scaling, axPos, crossAx, delete, ...` and reads an edited file in that order. When it saves again it adds `c:size val="7"` (line markers), `c:explosion val="0"` (pie), `c:smooth val="0"`, writes `c:numFmt formatCode=""`, and corrects `axPos` of a horizontal bar chart. Chart ids (`c:axId`) are renumbered on each save. It also adds, inside `c:dLbls`, `c:delete val="0"`, `c:showLeaderLines val="0"` and (line series) `c:dLblPos val="r"`; `cmpd="sng"` on `a:ln`; `c:invertIfNegative` on pie series; and writes colours in lower case. None changes the page; the reader treats them as defaults. Chart in a table cell, several charts, several sections and a file changed by `hd edit` keep the chart and draw it the same (B:x_cell, x_sections, x_edited). | P:chart_*; RT:chart_* |
| CH12 | Area chart: group `c:areaChart` (`c:grouping` `standard` or `stacked`, `c:varyColors 0`, series with `c:spPr` fill, `c:cat`, `c:val`, then the two `c:axId`); value axis `c:crossBetween val="midCat"` when every series is an area (the area starts at the axis), `between` in a combo. Spec: `type: "area"`, or a combo series with `type: "area"`. **Status: builder form from the OOXML standard; Hangul opened the builder file without a repair prompt, saved it again (`chart_area.hwpx`) and drew the two areas edge to edge with the category labels on the vertices.** | B:chart_area (Hangul render looked at); RT:chart_area |
| CH13 | Scatter chart: group `c:scatterChart` with `c:scatterStyle val="lineMarker"`; each series has `c:xVal` and `c:yVal` (`c:numRef`/`c:numCache`; the x values are the spec `categories`, numbers, shared by all series); markers only = `c:spPr/a:ln/a:noFill`, spec `lines: true` = a line colour in `c:spPr/a:ln`; two `c:valAx` (x `axPos b`, y `axPos l`, `crossBetween midCat`); spec `x_min`, `x_max`, `x_title`. **Status: as CH12 (`chart_scatter.hwpx`: markers and the line, numeric x axis 0 ... 5 in steps of 0.5).** | B:chart_scatter (render); RT:chart_scatter |
| CH14 | Secondary axis: a series with `axis: "secondary"` goes into a second chart group (own pair of `c:axId`); a second `c:valAx` (`axPos r`, `c:crosses val="max"`, spec `y2_title`, `y2_min`, `y2_max`) and a hidden second category axis (`c:delete val="1"`) follow the first pair. Horizontal bars: `axPos t`. At least one series stays on the primary axis. **Status: as CH12 (`chart_secondary.hwpx`: bars on 0-80, the line on the right axis 0-6, the axis title "비율" beside the legend).** | B:chart_secondary (render); RT:chart_secondary |
