# Text style: rules (Hangul 2024)

Rules TS01-TS20 for this package (`lib/hwpx_docs/textstyle/`). Evidence keys as in `docs/rules.md` (S: sample, P: pair, RT: round
trip, X: Hangul exploring run). Fixtures: `tests/fixtures/`. Rows that wait for Hangul are marked OPEN in `coverage.md`.

| id | rule | evidence |
|---|---|---|
| TS01 | COM custom tab stops: `HParaShape.TabDef` (`AutoTabLeft`, `AutoTabRight`, `TabItem`). `TabItem` is a flat integer array, THREE values per stop in the order (position in HWPUNIT, leader, type); `CreateItemArray("TabItem", 3 * n)` first, then `SetItem(i, v)`. Leader 0-11 = NONE, SOLID, DOT, DASH, DASH_DOT, DASH_DOT_DOT, LONG_DASH, CIRCLE, DOUBLE_SLIM, SLIM_THICK, THICK_SLIM, SLIM_THICK_SLIM (the line types, but DOT and DASH swap places with the corpus order). Type 0-3 = LEFT, RIGHT, CENTER, DECIMAL. Two values per stop, or the order (pos, type, leader), makes `Execute` return False. | X:tab probes |
| TS02 | XML: the paragraph's `hh:paraPr tabPrIDRef` names an `hh:tabPr id autoTabLeft autoTabRight` of `hh:tabProperties` (ids 0, 1, 2 are built in: no stop, auto left, auto right). EACH stop is its own `hp:switch`: `hp:case hp:required-namespace=".../2016/HwpUnitChar"` > `hh:tabItem pos type leader unit` and `hp:default` > `hh:tabItem pos type leader` (a switch that holds all stops is read wrong: the render differs). The REAL position is the case `pos` in HWPUNIT when `unit="HWPUNIT"`, and 5 times the case `pos` when `unit="CHAR"` (measured: case 2834 drew at 50 mm, 4251 at 75 mm, 7086 at 125 mm); the default `pos` is twice the case `pos`. The builder always writes `unit="HWPUNIT"`, case = the position, default = twice it. The reader takes the case value (x 5 for CHAR). | X:sweep of single stops 10-100 mm; RT:tab_* 17 files ink 0.00 |
| TS03 | COM asks for twice the position (like the paragraph margins, C05) and Hangul then writes unit HWPUNIT for the requests 10 + 30k mm and unit CHAR for the others; so a COM sample uses `2 x mm` of the wanted position and positions 5 + 15k mm (20, 35, 50, 65, 80, 95, 110) get HWPUNIT. Each ParagraphShape call ADDS stops to the ones the paragraph has (later paragraphs keep them). In the text Hangul writes `<hp:tab width="3725" leader="0" type="1"/>` (the gap width, the leader number, the type 1 = LEFT 2 = RIGHT 4 = DECIMAL 3 = CENTER?); the builder writes `width="0" leader="0" type="0"` and Hangul lays the line out from the stops (ink 0.00). | X:tabs_custom; RT:tabs_custom |
| TS04 | Spec: `tabs` of a paragraph = `[{"pos": mm, "type": "left|right|center|decimal", "leader": "none|solid|dot|dash|..."}]`, or `{"stops": [...], "auto_left": bool, "auto_right": bool}`. The reader writes `tabs` only for a tabPr that has stops. A tab character in the text is `\t`. | B:build -> read -> build -> read, `hd selftest --only textstyle` |
| TS10 | A named style is `hh:style id type="PARA|CHAR" name engName paraPrIDRef charPrIDRef nextStyleIDRef langID="1042" lockForm="0"` in `hh:styles` (the last item of `hh:refList` before `memoProperties`). The template has 23 (ids 0-22: 바탕글, 본문, 개요 1-10, 쪽 번호 (CHAR), 줄 번호 (CHAR), 머리말, 각주, 미주, 메모, 차례 제목, 차례 1-3, 캡션); a user style gets the next id. A CHAR style has `paraPrIDRef="0"` and `nextStyleIDRef="0"`. | S:blank; P:style_apply |
| TS11 | Applying a style (COM action `Style`, `HStyle.Apply` = style id) writes the paragraph with `styleIDRef` = the style id AND `paraPrIDRef` = the style's paraPr; the run takes the style's `charPrIDRef`. A style stays a label plus defaults: Hangul draws the paragraph from its own paraPr and charPr. | P:style_apply |
| TS12 | Spec: document `named_styles` = `{"name": {"type": "para|char", "eng": "Name", "next": "name of the next style", <para and char props, flat>}}`; a block `{"style": "name", "p": ...}` or a run `{"t": ..., "style": "name"}` uses it: the style's props go under the item's own props and a block gets `styleIDRef`. Built-in names (Korean or English) work without `named_styles`. A run has no style reference in the file, so `hd read` reports char styles in `named_styles` but not on runs. An unknown name stops the build. | B:`hd selftest --only textstyle` |
| TS14 | 덧말: COM `HAction Dutmal` returns False; `InsertCtrl("tdut", set)` makes a control but the HWPX that Hangul then saves has the paragraph with no run text and no `hp:dutmal`. The route is a file built by hwpx-docs and saved again by Hangul (`hd textstyle samples resave`): Hangul accepts and writes back exactly `<hp:dutmal posType="TOP|BOTTOM" szRatio="50" option="0" styleIDRef="0" align="CENTER"><hp:mainText>본말</hp:mainText><hp:subText>덧말</hp:subText></hp:dutmal>` as a child of the paragraph's `hp:run`, between the `hp:t` pieces of the same run (the OWPML model's names). The same element inside `hp:ctrl` makes Open fail. `option` is kept as given (the meaning of its values is not explored); `szRatio` 60 and align LEFT are kept. | RT:dutmal_top, dutmal_bottom, dutmal_wide ink 0.00 |
| TS15 | Preview (and the raw form of a file that is not read to the spec): a 덧말 kept raw as `{"xml": "<hp:dutmal posType szRatio align><hp:mainText>..</hp:mainText><hp:subText>..</hp:subText></hp:dutmal>"}` is drawn by `preview/drawers/dutmal.py` (sub text at szRatio %, default 50, centred above for TOP, below for BOTTOM; the object is as wide as the wider of the two). The form is the one Hangul writes (TS14); the drawing is an approximation of Hangul's, not measured against its pages. | B:hd selftest --only textstyle |
| TS16 | Preview, IN PROGRESS (layout owner, `[PC] HWPX 스킬`): custom tab stops and tab leaders are not drawn. `preview/layout.py emit_line` places `\t` on the default grid (`TAB` 14.11 mm) and draws no leader; the paragraph's `tabs` never reaches it. The fix is in layout.py (the stop list of the paragraph in the line, the stop's type for right/centre/decimal, a leader line between the text before the tab and the next text): hand-over note `hwpx-textstyle-preview-tabs.md` in the shared notes folder. | `hd preview` of a `tabs` file |
| TS17 | Drop cap (문단 첫 글자 장식), COM action `DropCap` with `HDropCap` (`style` 0 none, 1 two lines, 2 three lines, 3 margin; `FaceName`, `FaceColor`, `LineColor`, `LineStyle`, `LineWeight`, `Spacing`). Hangul makes the first character a floating text box: in the paragraph's first run `<hp:rect ... textWrap="SQUARE" textFlow="RIGHT_ONLY" lock="1" dropcapstyle="DoubleLine|TripleLine|Margin" ratio="0">` holding one paragraph (`hp:drawText` > `hp:subList` > `hp:p` with the character, a centred paraPr and a new charPr whose `height` is the box size), followed by `<hp:t>` with the rest of the text in the same run. Box size (`hp:sz`, `hp:orgSz`, `hp:curSz` 0) = 2600 (10 pt body, two lines: 16 + 10 pt), 4200 (three lines). `hp:parameterset > hp:listParam name="12291" > hp:unsignedintegerParam name="28673"` = the style number 1, 2 or 3. `hp:lineShape style="NONE"` and no fill by default; with a frame colour `style="SOLID"`, `hc:winBrush faceColor`. COM `LineWeight` is a width in HWPUNIT, not an index (the index 6 gave width 6) and `Spacing` is the right `hp:outMargin` in HWPUNIT (spec `gap`, mm). `FaceColor` is the box fill (`hc:winBrush faceColor`), `LineColor` the frame. Style Margin puts the box in the left margin: `hp:pos horzOffset` = 2^32 - box width (an unsigned negative number). | X:dropcap_s0-s3, dropcap_face |
| TS18 | 스타일마당: the COM action `StyleTemplate` returns False. Hangul opens a template `.hwp` as a document (hwpcom `open(path, fmt='HWP')`), so Open + SaveAs HWPX shows its styles: every ko-KR template (Book 5, Letter 5, Paper 3, Present 5, Report 4, Thesis 3 = 25) holds 12 styles (바탕글, 본문, 개요 1-7, 쪽 번호, 머리말, 각주) with its own shapes; Book5, Thesis1 and Thesis3 also carry many tab stops. Table of every template: `templates.md`. | X:25 templates; templates.md |
| TS19 | COM cannot create a user style: `StyleAdd` and `StyleEdit` return True with `HStyleItem` (NameLocal, NameEng, type, Next) but the saved file still has 23 styles; with int `ParaShape` / `CharShape` the call is refused. The route is a file built with `named_styles` and saved again by Hangul: it keeps every style (names, `engName`, `nextStyleIDRef`, CHAR style with `paraPrIDRef` 0 and `nextStyleIDRef` 0; an empty engName is written as `""`), writes the next ids 23-26 and the paragraphs' `styleIDRef`. A run keeps no style reference. | RT:styles_user ink 0.00; X:style_probe |
| TS20 | 한자 병기 (C8.07): the COM action `InputHanja` (`HInputHanja`, option 0-5) returns True on a selected word but changes no text; other names return False. A sample made by hand in Hangul (F9 on 대한민국, `hanja_dialog.hwpx`) shows the input forms of the dialog: 漢字, 漢字(한글) and 한글(漢字) are PLAIN TEXT in `hp:t` (`大韓民國`, `大韓民國(대한민국)`, `대한민국(大韓民國)`: no field, no style), so the builder needs no key (sample `hanja_forms`). | TS22 | Picture bullet (C2.19 = C8.08): COM sets `ParagraphShape` `HeadingType = 3` with `Bullet.HasImage = 1` and gets `<hh:bullet id char="●" useImage="1"><hc:img binaryItemIDRef="" .../>` but never loads the image (`FileNameStr`, `FileInfo`, `Embedded`, `ImageBrush` all leave `binaryItemIDRef` empty; the `BulletShape` action returns False).
