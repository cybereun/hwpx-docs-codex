# hwp5: rules

Rules HW01-HW113 of `lib/hwpx_docs/hwp5/` (the binary .hwp format, HWP 5.0). Evidence keys:
S = 한글과컴퓨터 「한글 문서 파일 형식 5.0」 revision 1.3 (the public format document);
X = a field layout cross-checked by reading an open-source reader (hwplib, hwp2hwpx: Apache-2.0; no code taken);
P = measured on 39 HWP/HWPX pairs of one document (the test pairs of hwp2hwpx): `tospec` of the .hwp against `core.read` of the .hwpx;
F = real files (44 hwplib samples, 12 forms and test files of rhwp, pyhwp and hwp.js, 42 pair files; not shipped);
R = independent readers: pyhwp 0.1b15 (records and models) and olefile 0.47 in strict mode read every written file;
H = a page drawn by Hangul itself: a Hancom 2020 page of the same file (rhwp test asset) set beside the preview's page, or Hangul 2024 on Windows (background) opening the edited file; T = `hd hwp selftest`.
Checked in Hangul 2024 (Windows, 2026-11-16): 35 of 35 edited real forms open with no prompt and Hangul lays the paragraphs without PARA_LINE_SEG out again (HW08).
Not checked: forms with a password or distribution flag (refused by design). Files written by `cfb.build` (`hd hwp fromhwpx`, `hd hwp build`) open in Hangul 2024 with the page count of their source (HW42). Run `hd hwp render f.hwp --backend hangul` on Windows once per release.

Notice required by the format document's licence, in the source (`__init__.NOTICE`), the help (`hd hwp`) and the README:
"본 제품은 한글과컴퓨터의 한글 문서 파일(.hwp) 공개 문서를 참고하여 개발하였습니다."

| id | rule | evidence |
|---|---|---|
| HW01 | An .hwp is a compound file (CFB v3, 512-byte sectors; v4 is read too). Streams: `FileHeader` (256 bytes, "HWP Document File", version, attribute bits), `DocInfo`, `BodyText/Section<N>`, `BinData/BIN<XXXX>.<ext>`, `PrvText` (UTF-16LE), `PrvImage` (GIF, BMP or PNG), `\x05HwpSummaryInformation`, `DocOptions/*`, `Scripts/*`. An "HWP Document File V3.00" file (한글 97) is not a compound file: refused with UNSUPPORTED. | S; F |
| HW02 | FileHeader bit 0: DocInfo and the sections are raw-deflated (zlib, window bits -15). Refused (core.protect, exit 4, nothing decrypted): bit 1 password, bit 2 distribution (배포용; its text is in encrypted `ViewText`), bit 4 DRM, bit 8 certificate encryption, bit 10 certificate DRM, bit 13 private information security. `edit` also refuses bit 14 (track changes). | S; F (distribution.hwp refused) |
| HW03 | Writing = `cfb.patch`: only the changed streams move. Every directory entry keeps its 128 bytes except the start sector and size of a changed stream (and of the root entry when the mini stream changes), so the red-black tree, class ids and times stay as Hangul wrote them (a full rewrite of the directory is what other projects report as "파일 손상"). A stream under 4096 bytes lives in the mini stream. Sectors a changed stream gives up are zeroed (the old text does not stay in the file); new sectors take free ones first, then the end; the FAT, mini FAT and DIFAT (files over ~7 MB) grow when needed. `cfb.build` writes the files of HW42 (HWPX -> .hwp, `hd hwp build`): olefile strict 0 defects and Hangul opens them. | S; R (62 files strict); T |
| HW04 | Records: 32-bit header = tag (10 bits), level (10), size (12; 0xFFF = a 32-bit size follows). A paragraph = PARA_HEADER (level L) + its PARA_TEXT, PARA_CHAR_SHAPE, PARA_LINE_SEG, PARA_RANGE_TAG (L+1) + controls (CTRL_HEADER, L+1). A list (table cell, caption, text box, header/footer, note) = LIST_HEADER followed by its paragraphs at the same level; a cell is a LIST_HEADER after the TABLE record of a `tbl ` control (paragraph count, attribute, then column, row, column span, row span at byte 8, width and height at 16, margins at 24, border fill at 32). The list before TABLE is the caption. | S; X; F (148 122 paragraphs) |
| HW05 | PARA_TEXT code units: 32 and up = characters; controls 1-3, 11, 12, 14-18, 21-23 (extended: an object, section, field start ...) and 4-9, 19, 20 (inline: field end, tab ...) take 8 units, the other codes below 32 one (10 line break, 13 paragraph end). The k-th extended control is the k-th CTRL_HEADER of the paragraph. PARA_CHAR_SHAPE = (position, char shape id) pairs in code units. | S; X; F (encode = original for 148 121 of 148 122 paragraphs; the one left had a redundant pair) |
| HW06 | An edited paragraph: PARA_TEXT and PARA_CHAR_SHAPE are written again from the units (one char shape id per unit, then runs), PARA_HEADER gets the char count (bit 31 "last paragraph of its list" kept), the char shape count and the tab / line-break bits of the control mask (the mask is otherwise the controls' bits, measured: 148 008 of 148 122 paragraphs; the rest are hwplib-written files); PARA_RANGE_TAG positions follow the text. A paragraph left with only its end has no PARA_TEXT (char count 1): Hangul calls the file damaged otherwise. | S; F; reports of rhwp and hwpkit |
| HW07 | `set`: in a paragraph with a field (누름틀) the first field's content takes the text and the text around it stays; else the longest run of text between controls takes it in its most used char shape and the other runs are emptied (as `hd edit` for HWPX). `replace` works inside a run of text (characters, tabs, line breaks), each new character taking the char shape of the first one it replaces; across a field or object it sets the paragraph text (as HWPX `edit`). `check` changes ☐/□ before a label into the mark. Labels: as `hd edit`, and also without a leading item mark ("○ 사 업 명 :" = "사업명"). | T; F (forms) |
| HW08 | The line layout cache (PARA_LINE_SEG) of an edited paragraph is removed and its count in PARA_HEADER set to 0: Hangul lays the paragraph out again when it opens the file (hwplib, kordoc, hwp-fill and rhwp do the same; a cache that points past the text makes Hangul 2022 show a blank page, rhwp). Other paragraphs keep theirs. | S (it is a cache); X; H (Hangul 2024, Windows, background: 35 of 35 edited forms with a long text open and the edited paragraph has no PARA_LINE_SEG; Hangul's own SaveAs copy has the lines again, in a narrow cell 30 lines; the page picture shows them) |
| HW09 | PrvText becomes the text of the body and the table cells (cells as `<text>`, as Hangul writes it; first 1024 characters), PrvImage a white image of the same size and format, so neither shows the old text. Every other stream keeps its bytes. | T |
| HW10 | `edit` refuses to write over its input (the original is the guard's reference). | T |
| HW11 | DocInfo: ID_MAPPINGS gives the counts; FACE_NAME records come per language (한글, 영문, 한자, 일어, 기타, 기호, 사용자); BORDER_FILL ids count from 1, the rest from 0. | S; P |
| HW12 | CHAR_SHAPE and PARA_SHAPE are read into the spec names of core.read (P: 18 197 of 18 215 values equal; the 18 left are `outline_level` of outline styles, kept off the spec as core.read does). Paragraph margins, indent, spacing, fixed line spacing and tab positions are stored at twice HWPUNIT (spec pt = value / 200). Word break bit 7: 1 = char, 0 = word. | P |
| HW13 | BIN_DATA: an embedded item is `BinData/BIN%04X.<ext>`; its stream is raw-deflated when the document is. | S; F |
| HW14 | Border line types: 0 none, 1 solid, 2 dash, 3 dot, 4 dash-dot ... 17; widths 0-15 = 0.1 ... 5.0 mm. Drawing objects, picture borders and tab leaders number 2 = dot, 3 = dash (the other way round; hwp2hwpx notes the same). | P; X |
| HW15 | Guard STRUCTURE: every stream but the sections, PrvText and PrvImage keeps its bytes; per section the record tree without the paragraphs' text records is the same; every other record keeps its bytes (PARA_HEADER except the counts HW06 may change); an edited paragraph keeps its controls in order and uses no char shape it did not have. | T; F |
| HW16 | Guard BUDGET: the lines before are Hangul's own (PARA_LINE_SEG count of the original); after = before + (lines of the new text - lines of the old text), both estimated with core.textfit in the width Hangul used (the widest line segment) and the paragraph's font; the growth in mm uses Hangul's line height + spacing. | T; F |
| HW17 | Guard RESIDUE: forbidden / required words, placeholders (○○, {{...}}, XXX, ___), long sentences left (as HWPX `guard`). | T |
| HW18 | Guard `--render dir` adds the page comparison (HW27, HW28) to the result. | T |
| HW19 | tospec reads a section as core.read reads one (and adds `hangul_lines` to each paragraph that has a PARA_LINE_SEG: Hangul's own line starts in content units, preview rules P19): page from the `secd` control's PAGE_DEF (A4 = 59528 x 84186; start page at byte 20 of `secd`), page border from PAGE_BORDER_FILL, columns from `cold`, header / footer (`head` / `foot`, apply = both, even, odd), page number (`pgnp`). | P (19 of 39 pairs give the same spec; the other 20 differ only in objects core.read keeps as raw XML: arc, connector, OLE, and one stray field end) |
| HW20 | Common object properties (CTRL_HEADER of a table, drawing object, equation): attribute, y, x, width, height at byte 4; outer margins at 28. Attribute: bit 0 treat as character, bits 3-4 vertical reference (paper, page, paragraph), bits 8-9 horizontal (paper, page, column, paragraph), bit 13 flow with text, bits 21-23 wrap: 0 square, 1 top and bottom, 2 behind text, 3 in front of text. | P (36 objects) |
| HW21 | Tables: TABLE = attribute (bits 0-1 page break, bit 2 repeat header), rows, columns, cell spacing, inner margins at byte 10; column widths and row heights are solved from the cells as core.read does; grid lines keep the stronger of two cell sides. Cell attribute bits 5-6 vertical alignment, bit 16 own margins. A block table that takes its place in the text (wrap top and bottom), anchored to its paragraph, moving with the text, at the left of its column is a flow table whatever its offsets (the reader keeps them in `pos` with `flow` true; the preview turns them into outer margins and puts the text of the paragraph above the table, `core.build` writes them as the table's position): Hangul cuts it at page ends (a 138-row table over 9 pages of Hancom's print); a page the table goes on to has only the outer margin, not the offset (`margin_cont`; delegation pages 8-31: first line 0.5 mm under the body top); any other floating table gets `pos` like table.ext.read_pos. Header rows: only the title rows (cell attribute bit 18) at the top of the table, as Hangul repeats them. A caption gets side, label, number, text. | P; golden set |
| HW22 | Drawing objects: SHAPE_COMPONENT starts with the kind (`$pic`, `$rec`, `$ell`, `$lin`, ... twice at the top level), sizes, the transform matrices, then the line (colour, width, attribute: bits 0-5 type, 10-15 / 16-21 arrows) and the fill. Picture: border at byte 0, the bin id at byte 71 of SHAPE_COMPONENT_PICTURE. Line ends: SHAPE_COMPONENT_LINE. Rounded rectangle: first byte of SHAPE_COMPONENT_RECTANGLE. Text box: LIST_HEADER (attribute at 4, margins at 8) under the shape. | P; X |
| HW23 | Fields: `%clk` (누름틀; name after the command), `%hlk` (link; target = command up to ";"), other fields keep their text; `fn  ` / `en  ` notes, `atno` page number, `bokm` bookmark, `nwno` new page number, `eqed` equation (EQEDIT: script, size, colour, baseline). | P |
| HW24 | Anything else (arc, polygon, curve, container, OLE, chart, form objects ...) is counted (UNSUPPORTED on stderr); for the renderer it becomes a red dashed box of its size "NOT DRAWN <kind>" and a line `PREVIEW NOT DRAWN hwp <kind>`: never a silent blank. | T |
| HW25 | Render, backend preview: HWP -> spec -> the preview package through `registry.backend('specpages', 'preview')` (no HWPX in between, so `hangul_lines` reaches the layout): SVG + HTML everywhere, PNG with Edge on Windows. It is an approximation: without GDI and Hangul's fonts the widths are estimated (core.textfit; symbols that Korean fonts draw full width count 1 em) and another font is drawn; the reference for a form check is Hangul's own page (backend hangul, `auto` is the preview; Hangul is used only with `--backend hangul`, HW109). Backend hangul: Hangul opens the .hwp with the format "HWP" (render.hwpcom). | T; H (labnote form, page 1: same tables, positions, fills as Hancom 2020; backend hangul on Hangul 2024, Windows: 35 edited forms opened, pages written, `compare` ink difference in percent) |
| HW26 | (replaced by HW29-HW36: `hd hwp tohwpx` no longer goes through the spec; `tospec` is the approximate route for the renderer only.) | P |
| HW27 | Compare (preview): one SVG element per line; text elements and the others (lines, rectangles, pictures) are compared as multisets per page. FORM = an element other than text moved or changed (a row grew, a box moved): the edit changed the form; TEXT = only text changed; also the page count. | T; F |
| HW28 | Compare writes `<stem>_compare.html` (before | after; red boxes on changed text, blue on moved lines and boxes; no script, a content security policy) or, with Hangul, `<stem>_compare_p<N>.png` and the ink difference per page (render.img). | T |
| HW29 | `hd hwp tohwpx` = owpml.py: records -> OWPML, no spec in between (`owpmlmap` tables and XML writer, `owpml` package + header.xml, `owpmlsec` paragraphs / runs / sections, `owpmlobj` controls, `owpmlshape` drawing objects, `owpmlpkg` the other parts). A record or control with no mapping, or a value no pair shows (a spelling that is not known), stops it: `UNSUPPORTED <what> <where>`, exit 5. Nothing is dropped quietly. | P |
| HW30 | header.xml: ids from 0 (border fills from 1); FACE_NAME -> hh:font (+ typeInfo); BORDER_FILL; CHAR_SHAPE (colours as #RRGGBB, #AARRGGBB with an alpha byte, `none` for 0xFFFFFFFF); TAB_DEF (hp:switch, case = half); NUMBERING 10 levels (`checkable` = low bit of the format number; a 7-level record is padded with zero levels by Hangul 2018+); PARA_SHAPE (margins in hp:switch: case = value / 2, an odd value is a count of characters (unit CHAR, value >> 1), default = the stored value; outline level 7-10 in an hp:switch with the field after `line spacing`); STYLE; word break bit 7 set = KEEP_WORD. Left out by Hangul too: bullets, memo shapes, forbidden words. | P |
| HW31 | Section: one `hp:run` per PARA_CHAR_SHAPE pair; a tab, line break, hyphen, no-break and fixed-width space are elements inside `hp:t`; an extended control character takes the next CTRL_HEADER of its paragraph and closes the text; an empty `hp:t` ends the last run of a paragraph that has controls. Hangul 2018+ ends the first run after the columns control (`legacy` = a 5.0.5.x file: not). `hp:p@id` = the instance id; `pageBreak` / `columnBreak` = break bits 2 / 3. Master pages: secd attribute bits 29 / 30 / 31 = BOTH / EVEN / ODD exist, in file order; `masterpageN.xml` counts over the document. | P |
| HW32 | Object header: attr, y, x, width, height, z order, outer margins, instance id, description (HW20); offsets are written unsigned. A table: TABLE (attr bits 0-1 page break TABLE / NONE / CELL, bit 2 repeat header, margins, per-row counts, border fill), caption = a LIST_HEADER before TABLE (list header = count int32, attr; caption attr, width, gap, text width), a cell = LIST_HEADER (attr bits 16-19 own margin / protect / header / editable, address, span, size, margins, border fill). | P |
| HW33 | Drawing object: SHAPE_COMPONENT = kind id (twice at top level, once in a container), offset, level, sizes (curSz written as 0 for a side that equals orgSz), flip / rotate bits (bit 19 = rotateimage), matrices (translate, n x scale + rotate; 6 decimals), then line (colour, width, attr, outline byte), fill, extra length + bytes (a gradient keeps its step centre), one byte, shadow (type, colour, x, y), instance id, line alpha, shadow alpha. Rectangle, ellipse, arc, polygon, curve, line, connect line, container, text art: the record below it (HW22). A shadow adds room to the margin in the HWP; the saved HWPX has the user's. | P |
| HW34 | Picture: border, 4 corner points, crop (left top right bottom -> left right top bottom), margins, bright, contrast, effect, BIN_DATA number, line alpha, instance id, effects (flag word: 1 shadow, 2 glow, 8 reflection; floats; colour 0x00RRGGBB with colour effects), image size. OLE: attribute, extent, BIN_DATA number, border; its stream is the compound file (4 bytes of its directory differ from Hangul's own save). BinData is named `image<k>` / `ole<k>` by the BIN_DATA record number k. | P |
| HW35 | Fields: `%clk` CLICK_HERE, `%bmk` BOOKMARK, `%unk` with a `MEMO/...` command = MEMO (author, number, date; the date is written +9 h as the pair shows: KST assumed); fieldid = the control id as a number (a memo: `%%me`); the field end is an inline control (code 4) that closes the innermost open field. Other fields stop the conversion. Forms: the text property set of FORM_OBJECT (`Key:type:value`, `set:N:` nests, `wstring:N:` is N characters) -> btn, checkBtn, radioBtn, comboBox, edit. | P |
| HW36 | What the pairs cannot show: version.xml, container.rdf, manifest.xml and the spine's `linear` say which Hangul build saved the pair; the caret, the last-save user and date likewise; font typeInfo (Mac builds omit it); `Preview/PrvImage` is re-encoded. `tools/verify.py tohwpx` leaves exactly these out and prints every other difference (its NORMAL table). | P |
| HW37 | HWPX -> .hwp (`fromowpml.py`, `fo_head.py`, `fo_body.py`, `fo_shape.py`, command `hd hwp fromhwpx`): OWPML elements are written as the records they correspond to (CHAR_SHAPE <-> hh:charPr, PARA_SHAPE <-> hh:paraPr, CTRL_HEADER `tbl ` <-> hp:tbl ...); no spec in between. The records are compared with the .hwp Hangul saved of the same document (`tools/verify.py fromhwpx`, env `HWP5_PAIRS`): 36 of the 41 pairs of hwp2hwpx are record for record equal (the comparison lists its normalisations: `NORMALISE` of `tools/verify.py`). A pair that does not convert or differs is listed with its reason, never skipped. | P |
| HW38 | DocInfo written from header.xml: ID_MAPPINGS = the counts (18 integers; 16 before 5.0.3.0), FACE_NAME (attribute 0x40 = type info; the PANOSE serif style byte is not in the HWPX: Hangul's value by font name; the default font name is not written), BORDER_FILL (fill = type, parts, a size and that many bytes, then the transparency byte: solid size 0, gradient size 1 + step centre; hatch / face colour keep their alpha), CHAR_SHAPE 74 bytes, TAB_DEF (the `hp:default` branch as it stands: twice the HwpUnitChar value), NUMBERING (7 levels, a start word, 7 start numbers; levels 8-10 after them), PARA_SHAPE (46 / 54 / 58 bytes by version; outline level in bits 25-27 up to 6 and, from 5.1, in a field of its own up to 10; margins and line spacing from the `hp:default` branch, the heading from the `hp:case` branch), STYLE (a character style has paragraph shape 0). Constant records: FORBIDDEN_CHAR, compatible document (flags all 0), layout compatibility (all 0), track change (flags + zeros). | P |
| HW39 | The FileHeader version is the HWPX `version.xml` (major, minor, micro, build); record layouts depend on it (HW38). Written: compression on (bit 0), `HwpSummaryInformation` (an OLE property set from the opf metadata of content.hpf), `PrvText` (UTF-16LE of Preview/PrvText.txt), `PrvImage` (the HWPX one, if any), no `Scripts/` (the HWPX has no script; a script part makes Hangul show its security-level window), `BinData/BIN<XXXX>.<ext>` (the content.hpf items in order, ids 1, 2 ...). No `DocOptions/_LinkDoc` (it holds a path). | F; R |
| HW40 | Paragraph: PARA_HEADER (bit 31 of the character count on the last paragraph of every list; control mask = the control codes used; break bits: 3 for the paragraph with the section definition, 4 page, 8 column; instance id = hp:p id), PARA_TEXT, PARA_CHAR_SHAPE (a pair at each run whose char shape differs from the one before), PARA_LINE_SEG only when the HWPX has a linesegarray (the builder's HWPX has none: count 0, Hangul lays the paragraph out when it opens it, HW08). Text: tab = code 9 + width (4) + leader, type + three spaces + code 9; line break 10; no-break space 30; fixed-width space 31. Control characters: section / column definition 2, field begin 3, field end 4 (the id with the property in its last byte, then the editable bit, +2 inside another field), table / drawing object / equation 11, hidden comment 15, header / footer 16, note 17, automatic number 18, page number position / new number / hide 21, bookmark 22, ruby / compose 23. | P; R |
| HW41 | Objects: CTRL_HEADER = id, attribute (bit 0 as char, 3-4 / 5-7 vertical relation / align, 8-9 / 10-12 horizontal, 13 flow with text, 14 overlap, 15-17 / 18-19 width / height criterion, 21-23 wrap, 24-25 text flow, 26-28 numbering kind; bit 29 = the object has a caption: measured in Hangul, the bit goes when the caption goes, and a file with a caption but no bit is refused), offsets, size, z order, outer margin, instance id, description (CR LF line ends). `holdAnchorAndSO` has no bit of its own (Hangul saves the same attribute for 0 and 1; setting bit 29 for it made Hangul refuse the file). SHAPE_COMPONENT = kind twice, offset, group level, sizes, flags (bit 19 for rotateimage, bit 24 for a shape with text, `$pic` adds 0x24000000), rotation, 3 matrices; then line (colour, width, attribute with the arrows numbered EMPTY_DIAMOND 4, EMPTY_CIRCLE 5 ..., outline style), fill, shadow, instance id, line alpha, shadow alpha. Records: rectangle (round ratio + 4 points), ellipse, arc, polygon, curve, line, container (the child kinds, then the children with their kind written once and two or more matrix pairs), picture (border, image rectangle, crop, margins, bright, contrast, effect, BinData id, border alpha, instance id, 4 bytes, original size), equation (EQEDIT). Tables: TABLE (page break NONE 0 / TABLE 1 / CELL 2, repeat header bit 2, rows, columns, spacing, margins, cells per row, border fill, 0), caption LIST_HEADER (30 bytes) before it, then a LIST_HEADER per cell (47 bytes: count, attribute, address, span, size, margins, border fill, width again). Header / footer / notes / hidden comment: LIST_HEADER (34 / 16 bytes) + paragraphs. | P |
| HW42 | `cfb.build` writes real files: sector size 512, mini stream under 4096 bytes, FAT and DIFAT sized for themselves, directory entries in a red-black tree (every path the same number of black nodes), storages and the root with FILETIME stamps. olefile in strict mode finds 0 defects in the 35 written files, pyhwp reads them with 0 errors (paragraph counts, character shape pairs, line segments), and Hangul 2024 opens them with no repair question. | R; F |
| HW43 | An element, attribute value or section setting with no record yet stops the conversion: `UNSUPPORTED <what> <where>`, exit code 5, no output file (written to a temporary name and moved when done). Measured and written later: section visibility, line numbers, vertical text and its width head, manuscript paper, drawing captions (HW67, HW68, HW73), substitute font, bullet, image fill (HW66), shadow kinds (HW65), WordArt shapes and soft edge / colour effects (HW70, HW71), picture bullets (HW72), memo shapes (HW73), every OLE object type and drawing aspect (HW74). | T |
